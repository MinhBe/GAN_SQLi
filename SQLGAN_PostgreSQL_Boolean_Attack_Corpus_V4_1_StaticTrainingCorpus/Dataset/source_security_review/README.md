# Security1/Security2 review

Security1/Security2 were used to shape dataset organization, not to copy exploit procedures. The relevant lesson is evidence tiering: generated candidate, static accepted, parser/runtime accepted, and future observation/triage views must be separated.

This V4.1 artifact remains PostgreSQL-only, Boolean-only, and payload-only for the generator corpus. Contextual delivery, WAF logs, DAST evidence, and second-order flows are reserved for future datasets or LLM hard-case review.
