# Branch C — C-SeqGAN-Minimal

This patch adds the first executable version of the ruleset-conditioned SeqGAN plan for `SQLGAN_PostgreSQL_Boolean_CSeqGAN_V5_1_CoverageFixed`.

## Design decision

The model remains SeqGAN-based, but the generation task is changed from:

```text
G(payload)
```

to:

```text
G(payload | ruleset_id, structure_cell_id, family)
```

The implementation uses prefix conditioning instead of changing the LSTM architecture:

```text
<RULE=...><CELL=...><FAMILY=...> payload
```

This is intentionally minimal: it is the smallest implementation that makes the model target-aware and lets the reward measure whether the generated row matches the requested ruleset.

## Hardware target

The default smoke configuration is intended for:

```text
CPU threads: 2
RAM: ~30 GB
GPU memory: ~15 GB
GPU count: 1 or 2
```

If two CUDA devices are visible, Branch C can train Y1 and Y2 in parallel: Y1 on `cuda:0`, Y2 on `cuda:1`. If only one GPU is visible, it falls back to sequential mode on `cuda:0`.

## One-command smoke run

```bash
python -m sqlgan_dual.experiment_c_conditioned_seqgan \
  --data /content/GAN_SQLi/SQLGAN_PostgreSQL_Boolean_CSeqGAN_V5_1_CoverageFixed.zip \
  --out /content/runs_sqlgan/branch_c_cseqgan_minimal_smoke \
  --modules Y1_basic_boolean Y2_boolean_variation \
  --limit 2048 \
  --max-len 256 \
  --batch-size 160 \
  --mle-epochs 6 \
  --d-epochs 1 \
  --adv-epochs 1 \
  --adv-steps 25 \
  --emb-dim 128 \
  --hidden-dim 256 \
  --temperature 0.85 \
  --static-weight 0.45 \
  --generate-per-ruleset 2 \
  --generate-ruleset-limit 100 \
  --parallel-modules auto \
  --cpu-threads 2
```
